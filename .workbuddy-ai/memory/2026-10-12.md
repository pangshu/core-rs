# 2026-10-12

## 配置子系统：支持 toml / yaml / json 三种格式

**需求**：业务应用配置文件格式多样，配置解析需同时支持 toml、yaml、json。

**实现**：
- `Cargo.toml`：`config` 依赖 features 由 `["toml"]` → `["toml","yaml","json"]`（yaml feature 同时覆盖 `.yaml`/`.yml`）。
- `src/config/source.rs`：
  - 新增 `pub enum Format { Auto(默认), Toml, Yaml, Json }`，含 `extension()` / `candidates()` / `from_extension()` / `to_file_format()`。
  - `LoadOptions` 新增 `pub format: Format` 字段 + 链式 `.format(fmt)`；`new()` 默认 `Auto`。
  - `build_config` 不再用 `File::with_name`（其按扩展名猜测），改为 `resolve_file()` 探测 + `File::new(path, format)` 显式指定格式。
  - **关键设计（已拍板）**：`Auto` 按 `toml → yaml → yml → json` 优先级取第一个存在的文件；同名多格式共存时只加载优先级最高者（不叠加）。`default` 与 `{env}` 两层各自独立探测，允许混搭（如 default.toml + production.json）。toml 优先保证兼容既有工程。
- `src/config/watch.rs`：`watched_files()` 改走 `resolve_file`，热更新随格式自适应。
- `src/config/mod.rs`：导出 `Format`；模块文档更新。
- `docs/03-框架使用指南.md`：配置章节改为「多环境 + 多格式 + 热更新」，补充三格式等价示例与 `LoadOptions::format` 用法。
- `tests/core_test.rs`：新增 7 个用例（toml/yaml/yml/json/优先级/显式指定/环境层覆盖）。

**验证**：`cargo test --lib --tests` 全绿（42 lib + 29 集成 + 1 fixes，含新增 7 例）；demo 示例 `cargo check` 通过。doctest 因 Windows 管道耗尽（Os error 231）失败，属环境问题，与改动无关。

**注意**：`LoadOptions` 新增了 pub 字段 `format`，若外部有结构体字面量构造需补该字段（框架内统一用 `new()`，无影响）。

## 通配符（泛域名）证书匹配方案（评审稿，未改代码）

**诉求**：v1 TLS 仅精确域名匹配，站群场景需要 `*.example.com` 泛域名证书。

**产出**：`docs/09-通配符域名证书匹配方案.md`。核心结论：**纯匹配层增强，只改 `src/tls/store.rs` 一个文件**，
`CertProvider`/`CertEntry`/配置/热更新/`mod.rs`/`serve.rs`/`reload.rs` 全部不动，v1 三条边界不变。

**要点**：
- 匹配规则按 RFC 6125/9525：`*` 只占最左整 label、只出现一次、只吃一层 label、不匹配裸域、label 数须一致。
- 优先级：**精确 > 通配 > 未命中（握手失败）**。因限定「只吃一层」，同一 SNI 至多命中一条通配 → 无需优先级队列。
- 数据结构：`CertStore.map` 拆成 `exact` + `wildcard` 两张 HashMap；`not_after` 键保留 `*.example.com`。
- `build()` 按 `*.` 前缀分流 + `is_valid_wildcard()` 校验；`parse_certified_key()` 不动（整批失败 fail-safe 保留）。
- `lookup()`：精确优先 → `sni.split_once('.')` 拼 `*.{rest}` 查通配表（一行覆盖全部规则，无需正则）。
- 顺带修坑：v1 里业务塞 `"*.example.com"` 会成静默死条目（SNI 永不为字面量），新增校验拦下。

**决策点（4 项全部已拍板 2026-10-10）**：
1. ✅ `wildcard` 键保留 `*.example.com` 完整前缀。
2. ✅ 非法通配模式 → **跳过该条 + warn 告警（不拒绝整批）**。关键理由：业务层是**管理员动态添加域名**场景，
   改一条必须马上生效，不能让一条格式笔误拖垮整批（故障面放大）。**但 PEM 解析失败仍保持整批失败**（区分对待：
   域名层「跳过」、内容层「整批」）。
3. ✅ 加「精确条目被泛域名覆盖」冗余告警（非拒绝；纯提示，用于清理「先单签后买泛域名」的历史冗余证书）。
   实现注意：冗余检查要在整批 build 完成后统一做，避免条目顺序导致漏判。
4. ✅ 沿用「`*.` 后须含至少一个点」（拒 `*.com`；`*.co.uk`/`*.example.com` 合法）。

**方案已定稿**（`docs/09` 决策记录 §十、§5.1/5.2/5.3、§八测试、§九落地步骤均同步）。

### v2 优化复审（用户要求「分析方案并优化」）

通读初稿发现 **5 处可优化（2 处潜在 bug）**，已全部改进（见 `docs/09` §6.1）：
1. 数据结构从「`exact` + `wildcard` 两张表」→ **`map`（键保留原形，含 `*.x`）+ `wildcard_index`（后缀→模式键）**；
   `not_after` 与 `map` 键天然一致，省一份同步。
2. `lookup()` 通配命中改为**预计算索引 O(1)**（原每次握手 `format!("*.{rest}")` + 隐含依赖模式已小写）；
   并显式写入**「入参已归一化」调用契约**（既有契约，store.rs:127-128）。
3. **空后缀隐患**：SNI 为单 label（`localhost`）时，`split_once` 返回 `None` 而非空串 → `rest` 不会为空、`get("")` 不可能；
   叠加 `is_valid_wildcard` 拒 `*.`，双重保证。新增单测 9。
4. 更正 v1「死条目」表述 → 「**无效条目**」（不命中也不报错）；`*.x` 在 v1 下永不命中 map.get。
5. 补 **§4.6 `is_valid_wildcard()` 规范**（三步：`*.` 前缀 / 单通配符 / 后缀含点）+ 逐条对照表（原方案只有测试列举、无函数规范）。

**其他澄清**：空域名仍整批失败（与 v1 一致，不改）；`.rsplitn` 表述已删（未采用）。
测试清单更新为：单测 9 条 + 集成 3 条。方案状态 → **定稿 v2**。

**用户偏好**：要求方案解释必须**具体举例**、把「会出什么意外」讲清楚，不接受抽象描述。

### 通配符证书匹配 —— 已实现（2026-10-10）

**改动文件（零新增依赖，纯匹配层）**：
- `src/tls/store.rs`（核心）：
  - `CertStore` 结构改为 `map`（键保留原形，含 `*.x`）+ `wildcard_index`（后缀→模式键）+ `not_after`；
  - `build()`：空域名仍 `Err(Missing)` 整批失败；**非法通配 `continue` 跳过 + warn**；PEM 失败仍 `?` 整批失败；
    通配条目写 `wildcard_index`；整批后调 `warn_redundant_exact()` 做冗余告警。
  - `is_valid_wildcard()`：`*.` 前缀 + 后缀不含 `*` + 后缀含点（三步）。
  - `lookup()`：`map.get(sni)` 精确优先 → `split_once('.')` 后缀查 `wildcard_index` → 回查 `map`（O(1)）。
- `src/tls/mod.rs`：`CertEntry.domain` 注释更新（支持 `*.example.com`）。
- `tests/tls_test.rs`：新增 2 条集成（`wildcard_certificate_matches_subdomain`、`dynamic_load_skips_invalid_but_applies_valid`）。
- 文档：`docs/09` 状态改「已实现」、§八/§九 更新；`docs/03` 服务端 TLS 章节加通配示例 + 常见坑（重编号）；
  `README` feature 表；`docs/08` SNI 优先级表述。

**验证**：`cargo test --features tls --lib --tests` → 52 lib（含 10 tls::store 单测）+ 22 core + 1 fixes + 5 tls_test 全绿；
`cargo check`（默认 / `tls`）无代码告警（仅 Windows incremental 文件锁的环境告警）；demo `cargo check` 通过。

**注意**：`docs/09` §九 里旧的 `exact`/`wildcard` 两表描述是 v1 稿残留，最终实现是单 `map` + `wildcard_index`（见 §4.1/§6.1）。

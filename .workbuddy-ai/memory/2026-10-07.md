# 2026-10-07 工作日志

## 代码审查：中间件装配是否「业务端可选」（未改代码）

**问题**：业务端反馈「中间件是连续的，而不是让业务端自己选」，核实是否存在。

**结论：存在（部分成立）。** 证据：
- `src/app.rs` 的 `App::serve()`（约 268–312 行）把整条中间件链用连续 `.layer(...)` 写死，全局生效、顺序固定；`assemble_base`（web/router.rs）再叠 cors/compression/base_layers。
- `App<S>` 公开 API 只有 mount / mount_public / consumer / task / migrations / on_config_change / config —— **没有任何选择/排除/排序中间件的入口**。
- 业务端实际只能：①改 toml 开关或编译期 feature；②mount vs mount_public；③在自己路由树上「再加」`.layer()`（只能加，不能减、不能换序）。
- **完全无法关闭**（无任何开关）的层：CatchPanic、request_id、TraceLayer、access_log、auth(handle 恒执行)、body_limit、timeout。
- 有 `enabled` 开关的层（middleware/*.rs 内部读配置）：security_headers、ip_filter、rate_limit、idempotency、csrf、locale；cors/compression/metrics 由 web/router.rs + server 配置控制。

**附带发现（文档不一致）**：中间件顺序在三处注释里写法不同 —— `middleware/mod.rs`、`web/router.rs`、`app.rs` 的注释、`docs/03-框架使用指南.md` L289 各有一版，且 locale/trace 次序、csrf/idempotency 次序互相矛盾。`middleware/mod.rs` L15 与 docs L333 声称「组合权留应用」，与「框架全量全局装配」的实现不符（文档过度承诺）。

**给出的解决方案（未落地，仅建议）**：
- A 配置驱动：`[server.middleware] disabled=[...]` / `order=[...]`，serve 读取后跳过/排序（最贴合现有架构）。
- B 构建器 API：`App::middleware(|m| m.enable(..).disable(..).reorder(..))`（类型安全，API 面积大）。
- C 自组装：把 `assemble_base`/`base_layers` 提升为 pub，`App` 加 auto_middleware 开关（最灵活，但有 fail-open 风险）。
- 推荐折中 D：保留全量默认装配，给写死层补 `enabled`（默认 true 向后兼容）+ 增加 `without(layer_id)`；安全层关闭需显式并告警。

**项目级事实（长期有效）**：
- 中间件链的权威装配点在 `src/app.rs::serve` + `src/web/router.rs::assemble_base/base_layers`；`middleware/mod.rs` 自述为顺序依据，但已与实现不符。

## 产出：中间件「按业务可选 + 按场景调参」设计方案（未改代码）

**需求**：业务层开发时按不同业务逻辑选择不同中间件，且中间件参数可按场景调整。

**交付**：`docs/05-中间件按业务可选装配方案.md`（新建，纯设计文档，未动任何源码）。

**方案要点**：
- 三层作用域（全局 → 路由组 → 单路由）+ 就近覆盖；参数字段级 merge。
- 两种入口：A 配置档案 `[server.middleware.profiles.*]`（toml，可 extends）；B 代码 builder `.with_middleware(&profile)` / `.with(..).without(..)`。
- 中间件分三类：基础设施（panic/request_id/trace，全局锁定不可 per-route）、可选件（access_log/timeout/body_limit/cors/compression/ip_filter/rate_limit/idempotency/metrics/locale，可开关可调参）、安全件（security_headers/csrf/auth，只能 tighten_only + 放宽告警）。
- 落地骨架：axum `route_layer` / `MethodRouter::layer` 承载作用域；装配期解析 spec、闭包捕获参数（运行期零查表）；顺序仍由框架按 `middleware/mod.rs` 统一编排。
- 分期：P0 配置驱动（disabled + profiles + middleware_profile 引用）→ P1 代码 builder → P2 安全约束 tighten_only + 启动期打印解析结果。
- 验收：不声明档案时与现状逐层一致（向后兼容）。

## 统一时区方案落地（v3 定稿）

**背景**：日志时间戳显示 UTC（`2026-10-09T05:14:01.517800Z`）而非本地时区，排查后发现是全项目性问题，不止日志。

**设计原则（用户拍板）**：框架只提供"解析链 + 出口"，**不持有默认时区**。时区配置归业务层，
但入口落在框架 config（`[time].timezone`），非必填。

**解析链**：`[time].timezone`（已配置且合法 → 采用；非法 → 启动期 fail-fast）
→ 系统时区（`TZ` 环境变量 → OS 本地偏移）→ UTC（兜底）。

**改动清单**：
- `Cargo.toml`：`chrono-tz` 从 optional 提为**常驻依赖**（原只在 `scheduler`/`i18n` feature 下，
  但日志出口需在默认构建可用）；两 feature 中的重复声明已清理。
- `src/config/sections/time.rs`（新）：`TimeSettings { timezone: Option<String> }`，
  `timezone_name()` 归一化（空白串 = 未配置）。
- `src/config/settings.rs`：`Settings` 聚合 `pub time: TimeSettings`。
- `src/utils/time.rs`：新增解析内核 `resolve_display_tz`（全项目唯一时区解析入口）、
  `system_tz`（`OnceLock` 缓存 + `catch_unwind` 防 `chrono::Local` panic + 常见时区候选匹配）、
  展示出口 `display_rfc3339` / `format_display` / `now_display_rfc3339`。
  瞬时点出口（`now_ms`/`now_secs`/`now_utc`/`rfc3339`）**保持 UTC 不变**。
- `src/observability/logging.rs`：新增 `TzTimer`（实现 `FormatTime`），两个 fmt layer
  （console/json）各挂载；非法时区启动期 `panic` fail-fast。
- `src/task/cron.rs`：`resolve_job_tz` 走解析链，**修复文档 04:416 点名的"时区解析失败静默回落 UTC"缺陷**
  （改为 fail-fast）；`with_timezone` 重构为 `resolve_job_tz` + `build_job`。
- `src/config/sections/i18n.rs`：`default_timezone` 缺省值从 `"UTC"` 改为空串（未配置语义）。
- `src/i18n/format.rs`：新增 `format_datetime_default`（走解析链）。
- 文档：`docs/03` 新增第十一节·2「时区」、i18n 与 cron 章节同步；`docs/02` 新增 20.1 节；
  `docs/04` 勾销 cron 时区缺陷；`README.md` feature 表加 `time` 行；示例配置加 `[time]`。

**端到端验证**（临时工程实测）：配 `Asia/Shanghai` → 日志输出
`2026-10-09T13:58:04.505+08:00`；配 `Asia/Shanghi`（拼错）→ 启动 panic 且报错信息可操作。
测试：77 个全绿（47 lib + 5 + 22 core_test + 3）。

**硬约束（勿改）**：DB 审计字段入库、雪花 ID、JWT iat/exp、CSRF exp、各类 TTL 相对时长、
`Instant` 单调时钟 —— 全部必须保持 UTC。API JSON 里 `DateTime<Utc>` 默认仍序列化为 `...Z`。

**遗留**：日志 timer 在 init 时构造，改时区需重启（已写入文档）；
`fixed_offset_to_tz` 走固定偏移时无法处理 DST（已写入文档，建议显式配 `TZ` 或 `[time].timezone`）。

## 服务端 TLS 能力方案（评审稿，未改代码）

**诉求**：core-rs 目前零服务端 TLS；需支持 HTTPS，且**每个域名可经配置热更新 SSL 证书**（不重启）。

**现状定位**：`src/app.rs::App::serve()` 用 `TcpListener` + `axum::serve` 纯 HTTP；
配置 `ServerSettings`；热更新 `ConfigHandle<Settings>`(ArcSwap+subscribe) + `config/watch.rs`(notify)。

**方案要点**（详见 `docs/08-服务端TLS能力方案.md`）：
- 选型 `axum-server`(tls-rustls) + `rustls` 0.23；feature `tls` 默认关闭，关闭时行为与现状一致。
- 新增 `src/tls/`：`load`/`store`/`reload`/`serve`；核心是 `CertStore`(exact/wildcard/default)
  放进 `ArcSwap`，rustls `ServerConfig` **只构建一次**、内嵌 `DynamicResolver`(ResolvesServerCert)
  按 SNI 取证书 → 热更新只原子替换 CertStore，零重启。
- 配置新增 `[server.tls]`：`enabled`/`min_version`/`default_cert`/`default_key`/`[[domains]]`(domain,cert,key)/
  `redirect_http`。证书只以文件路径入配置，绝不内联 PEM。
- 热更新两条链：①配置变更(subscribe diff `[server.tls]`) ②证书文件变更(notify 监听目录)，
  都收敛到 `TlsState::reload()`；成功原子替换，失败保留旧值(fail-safe)；启动期首载失败则 fail-fast。
- 集成点：`CoreState` 加 `tls: Option<Arc<TlsState>>`；`serve()` 按开关二选一路径 + 优雅停机用 axum-server `Handle`。
- 非目标：ACME 自动签发、mTLS、HTTP/3、OCSP stapling(Phase2 可选)。
- **待用户拍板**：provider(ring vs aws-lc-rs)、证书相对路径基准、是否内置 HTTP 跳转端口、
  到期监控是否 v1 做、默认最低 TLS 版本。

### TLS 方案追加：证书来源可插拔（用户追问「能否放数据库」）

**结论**：能。rustls 握手只认内存 `domain→CertifiedKey`，来源（文件/DB/API）对它透明。
故抽象 `CertProvider` trait（`async fn load() -> Vec<CertEntry>` + 可选 `revision()` 做变更探测），
框架只定义契约与 DTO（`CertEntry{domain,cert_pem,key_pem}`），**业务实现取数**（查自己的表）；
内置 `FileCertProvider`，业务实现 `DbCertProvider`，`App::cert_provider(...)` 在 serve 前注册。
与既有 `HealthCheck`/`Authn` 注册模式一致，框架不认识表结构。

**要点**：
- DB 无文件事件 → 三种刷新触发：手动 `core.tls.reload()` / 周期轮询 `refresh_interval_secs` /
  经 queue 跨实例广播。
- 异步坑：`ConfigHandle::subscribe` 回调同步、DB 取数 async → 配置变更触发 reload 必须 `tokio::spawn`；
  文件 watcher 在 std 线程需捕获 `tokio::runtime::Handle` 再 spawn。
- 安全（重点）：私钥入库显著扩大暴露面（备份/复制/慢查询日志/DBA）→ 建议 AES-GCM 加密
  `key_pem`（KEK 走环境变量，复用 `security::crypto`）、DB 账号最小权限、审计、绝不进日志。
- 可用性：运行期证书常驻内存 ArcSwap，DB 宕机不影响在服务的 TLS；启动期 DB 来源 fail-fast。
- 推荐：主推 trait（业务无感）；可选内置 `DbCertProvider`（约定表 + 加密助手）作为 `tls-db` feature。
- 已更新 `docs/08`：新增「§十二 证书来源可插拔」+ §六集成点 + §十决策点 6。

### TLS 方案定稿边界（用户拍板）

**用户决定：框架内不要约定表；证书来源/判定/保存全在业务端。** 据此重写 `docs/08`：
- **框架零证书存储、零存储约定、不内置任何 provider**（`FileCertProvider` / `DbCertProvider` 都不进框架）。
- 唯一入口 `CertProvider` trait（`async load() -> Vec<CertEntry>` + 可选 `revision()`）；业务 `serve()` 前
  `App::cert_provider(...)` 注册；`tls.enabled=true` 但未注册 → fail-fast。
- `[server.tls]` **只放行为开关**：enabled / min_version / refresh_interval_secs / redirect_http / http_port；
  **无域名、无路径、无表名**。
- 模块：`src/tls/{mod,source,parse,store,reload,serve}.rs`（`load.rs`→`parse.rs`，只解析字节不读存储）。
- 热更新触发改为业务驱动三选：手动 `core.tls.reload()` / 周期轮询 `refresh_interval_secs` / 经 queue 广播；
  **去掉文件监听链**，`tls` feature 不再需要 notify。
- 安全：保管责任在业务层；框架侧只保证「日志/错误只出域名、绝不出 PEM」+ 解析失败 fail-safe。
- §十二 改为「业务侧如何提供证书（框架只给契约）」，DB/文件/KMS 均标注为**业务侧**做法，非框架约定。
- **待拍板**：provider(ring/aws-lc-rs)、HTTP 跳转是否 v1、到期监控是否 v1、默认最低 TLS 版本、轮询默认间隔。

### TLS 方案追加：目录模式（配置门控热更新+监控）

**新诉求**：框架给出一个 config 选择 —— 业务没配 TLS 目录 → 不需要热更新；配了 TLS 目录 → 需要热更新 + 监控链路。
**分析结论**：可做到，属框架惯用「配置门控能力」模式（同 `[server.metrics].enabled`、`[realtime].forward`）。
- `[server.tls]` 增加：`dir`(空=不启用目录模式) / `watch` / `debounce_ms` / `monitor`。
- 装配门控：`if let Some(dir)=tls.dir { spawn_dir_watcher(...); if tls.monitor { spawn_monitor(...) } }`；
  未配 dir → 不 spawn 任何后台任务。首次加载失败 fail-fast；运行期 reload 失败 fail-safe。
- **两个语义待用户拍板**：
  - **方案 B（我推荐）**：目录仅作**变更触发器**，框架监听目录→触发 `tls.reload()`→业务 provider 重新取数；
    **框架不读证书内容**，保持上一轮「不读证书/不定义存储约定/不内置来源」边界不变。
  - **方案 A**：目录即**来源**，框架内置目录来源直接读 PEM（需文件名↔域名约定），属对边界的**有意放宽**。
- 监控链路（仅目录模式启）：notify 变更监听（复用 config/watch.rs 防抖逻辑）/ 加载健康 /
  到期监控（`tls_cert_expiry_seconds{domain}` + `/ready` 探针）/ 目录可用性。
- 已更新 `docs/08`：§三配置加 dir 组、§八边界加例外说明、新增 §十三「目录模式」。

**用户拍板：采用方案 B（目录仅作触发器）。** 已锁进 `docs/08`：
- 框架新增的唯一东西是「一个受配置门控的目录监听器」——纯触发，不碰证书内容。
- `dir` 非空 → 启 watcher（触发 `tls.reload()`）+ 监控；`dir` 空 → 完全不监听、不 spawn。
- 边界不变：框架不读证书 / 不定义存储约定 / 不内置来源。
- 同步更新：§二依赖加回 `notify`（仅目录模式用）、§五热更新触发从三种变四种（+目录监听）、
  §六集成点、§十一落地步骤、§十三.3/13.7 标注已拍板。

### TLS 方案：5 项默认取值已定稿

用户拍板：①crypto provider = **ring**；②HTTP→HTTPS 跳转 = **可选项**（redirect_http 默认关）；
③到期监控 = **v1 一并做**（monitor_expiry 默认开）；④默认最低版本 = **TLS 1.2**；
⑤轮询间隔 = **默认 60s**（refresh_interval_secs 缺省 60，0=关）。

**一处重要澄清（已写入文档）**：轮询/手动/广播**与目录模式无关、始终可用**；目录模式（配了 dir）
额外提供「文件变更即时触发 + 目录可用性监控」。到期监控因框架本就要解析证书，**TLS 开启即生效**。
即：`monitor` 子键拆成 `monitor_expiry`（全局）；目录模式专属只剩 watcher + 目录可用性。

**另一处修正**：`CertProvider::revision()` 签名从 `Result<u64>` 改为 `Result<Option<u64>>`
（默认 `Ok(None)`）——避免「版本号恒为 0 → 永不刷新」的坑；返回 None 时轮询直接 load()。

已同步更新 `docs/08`：§二 2.1 选型表、§三配置、§四 4.2 trait、§五、§六、§七、§十（改决策记录表）、
§十一、§十三（13.1/13.2/13.4/13.5/13.7）。**方案已全部定稿，下一步可开工实现。**

### TLS 方案精简（用户要求「分析有没有不必要的内容」→ 全部采纳）

删 5 项冗余：①配置变更触发的证书重载（ConfigHandle::subscribe→reload，与轮询/目录/手动重叠）
②跨实例广播（queue，未要求）③`revision()` 可选方法（premature + Option<u64> 坑）
④`default` 兜底证书桶（无任何配置/provider 字段能填，悬空）⑤`watch` 配置键（配了 dir 就是要监听）。
简化 3 项：⑥到期监控双出口→只做 `/ready` 探针（不依赖 metrics feature，Prometheus 指标归 Phase 2）
⑦`src/tls/` 6 文件→4 文件（`{mod, store, reload, serve}.rs`，source 并入 mod、parse 并入 store）
⑧v1 去通配符 `*.`，只做精确匹配（`CertStore` 从 {exact,wildcard,default} 简化为单个 HashMap）。
结果：触发机制 4→3、trait 2 方法→1、`CertStore` 一张表、少 2 文件 / 1 配置键；功能面不变。
已按此重写 `docs/08`（整体精简版）。

# 逐行中文注释规范（core-rs 代码人工审核用）

## 目标
对指定 Rust 源文件的**每一行有效代码**，在**行尾追加一条中文注释**，形成「一行代码 ↔ 一条注释」的 1:1 映射，供人工逐行审核。

## 硬性规则（必须严格遵守）

1. **只加注释，不改代码。** 除追加 `// ...` 行尾注释外，不得改动任何字符：不重排、不重命名、不格式化、不删空行、不增删代码。代码语义必须逐字节保持不变。
2. **注释语言：简体中文。** 简洁、准确，说明该行「做什么 / 为什么」。单条建议 ≤ 40 字。
3. **仅注释有效代码行**。以下行**不加**注释：
   - 空行；
   - 仅由收尾符号构成的行：`}`、`);`、`};`、`},`、`]`、`);`、`)` 等；
   - 已有的注释行（`//`、`///`、`//!`、`/* */`）——它们本身就是注释，保持原样；
   - `#[cfg(test)]` 测试模块内部的**全部**内容（见规则 7）。
4. **行尾注释格式**：`<原代码> // 中文说明`。使用行注释 `//`，**不要**用 `///`（会变成文档注释）。
   - 若该行原本已有行尾 `//` 注释，**保持不动**，不要叠加第二条。
5. **多行结构**（跨行的函数签名、结构体字面量、链式调用、宏调用等）：在承载语义的那一行行尾加注释；其续行若也是有效代码，同样各自加注释。
6. **绝不可把注释插入字符串字面量内部**。多行字符串 / 原始字符串 `r#"..."#` 的每一行都**不加**注释（插进去会破坏字符串内容）。含 `format!`/SQL 等多行字符串同理，只注释字符串**之外**的代码。
7. **测试代码跳过**：遇到 `#[cfg(test)]`（通常后跟 `mod tests { ... }`）时，从该属性行开始到对应模块结束的**整个块原样保留**，不加任何注释。若文件末尾还有 `#[cfg(test)]` 的独立测试函数，同样跳过。
8. **属性行**（如 `#[derive(...)]`、`#[serde(...)]`、`#[cfg(...)]`）属于有效代码，正常加行尾注释。
9. 注释要贴合本项目语境（axum 0.8 / SeaORM 2 / 配置热更新 / 中间件 / 可插拔缓存队列等），避免空话套话。

## 风格样板
请先读 `src/traits.rs`（已按此规范完成），严格对齐其行尾注释风格。

## 输出要求
- 直接**原地覆盖写回**每个文件（Read 后 Write 整个文件）。
- 逐文件处理，不要遗漏。
- 完成后回报：处理了哪些文件、各文件是否含 `#[cfg(test)]` 块、有无任何不确定之处。
